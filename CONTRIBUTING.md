# Contributing

Thanks for helping build MacGlow.

1. Discuss substantial behavior or architecture changes in an issue first.
2. Keep changes focused and include tests for core logic.
3. Use public Apple APIs and document permission changes.
4. Run `swift test` before opening a pull request.
5. Never add telemetry, network calls, or persisted audio without explicit
   project-wide review.

Bug reports should include macOS version, Mac model, display topology, audio
output device, reproduction steps, and logs with personal metadata removed.
